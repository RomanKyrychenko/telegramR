# TL schema regeneration tooling (R)

The R6 classes in `R/types.R` and `R/functions_*.R` are generated from
Telegram's TL schema. This directory holds the R tooling that generates them,
so the package can be re-synced whenever Telegram bumps its API layer.

Everything here is build-time only; none of it ships in the installed package.
The scripts are plain `Rscript` programs (no extra dependencies beyond the
package's own: R6, and `digest` for CRC32).

## Files

- `api.tl` — vendored Telegram TL schema (layer 229), from Telethon v1:
  <https://codeberg.org/Lonami/Telethon/raw/branch/v1/telethon_generator/data/api.tl>
- `generate_tl.R` — the TL parser and R6 emitter. Also a CLI:
  - `Rscript data-raw/generate_tl.R api.tl` — layer / definition counts
  - `... --emit NAME` — print one generated class (for review)
  - `... --audit` — every existing class whose constructor id differs from the
    schema: `ClassName<TAB>current<TAB>schema<TAB>file`
  - `... --missing` — schema TYPES with no R6 class in `R/`
- `overwrite_stale.R` — regenerates classes in place, preserving each class's
  conventions (field names, `to_dict`/`toDict`, serializer name, inheritance):
  - `... api.tl audit.tsv --all-types` — regenerate every existing TYPE class
  - `... api.tl audit.tsv` — fix genuinely-stale FUNCTION constructor ids
  - `... api.tl audit.tsv --docs-only` — refresh only the roxygen block above
    each class; never touches the body, so call sites are safe
- `dedupe_types.R` — remove duplicate class definitions (keep the first).
- `emit_missing.R` — emit generated classes for schema TYPES absent from `R/`.
- `regenerate.R` — the full pipeline (see below).
- `layer229_audit.tsv` — output of `--audit` (regenerated by the pipeline).

## Doing a full layer bump

1. Drop the new `api.tl` into `data-raw/` and set `LAYER` in `regenerate.R`.
2. Run the pipeline from the package root:

   ```sh
   Rscript data-raw/regenerate.R
   ```

   It runs, in order: audit → dedupe `types.R` → regenerate all TYPE classes →
   fix stale FUNCTION constructor ids → append missing TYPES → document every
   class with roxygen (`#'`) → bump `LAYER` in `R/telegrambaseclient.R`.
3. Reconcile the hand-written readers in `R/binaryreader.R` (`.telegramR_read_*`
   for `Channel`, `Message`, `User`, `ChannelFull`, `ChatFull` and the
   `messages.*` containers) with the new layer's field layouts if they changed.
4. Validate: `devtools::load_all()`, the unit suite (`NOT_CRAN=true`), and the
   live smoke test (`inst/integration/smoke.R`) against a real account — the
   last is the only check that catches wire-level regressions.

## What the emitter produces

telegramR's **type** convention: snake_case fields, `to_dict()`/`to_list()`,
`bytes()` (or `to_bytes()` when a type has a `bytes` data field), a private
`from_reader()`, and `class = TRUE`. Function requests add a `Request` suffix
and inherit `TLRequest`; those with `InputPeer`/`InputUser`/`InputChannel`
arguments also get a `resolve()`. Serialization uses the package runtime helpers
(`pack`, `packInt64`, `serialize_bytes`, `serialize_datetime`,
`.telegramR_tl_vector`) and always emits little-endian constructor ids. Every
class gets an internal roxygen block (`#' @noRd`).

Structural cases handled and validated: multiple flag words (`flags`/`flags2`,
in declaration order), `true` flag-only fields, typed scalar vectors, reserved
R6 names and method-name collisions (sanitised with a trailing `_`), a `bytes`
data field (kept, serialised via `to_bytes()`), int128/int256, and namespace
collisions (bare-vs-namespaced types resolve to the bare name; function
collisions such as `channels` vs `account` `checkUsername` are disambiguated by
the existing class's constructor id, then by argument overlap).

## RESOLVED: full regeneration at layer 229 landed

The full regeneration is done and validated at layer 229. The R pipeline is
**idempotent**: running `regenerate.R` on the current sources reproduces them
exactly (constructor ids, field layouts, serializers), which is how the port
from the original Python tooling was verified — 959/959 scalar-constructible
types round-trip byte-for-byte, the unit suite is green, and
`inst/integration/smoke.R` passes all documented flows live.

Note on FUNCTION classes: the pipeline only rewrites a request's body when its
constructor id genuinely differs from the schema. Namespace collisions (e.g.
`channels.deleteHistory` vs `messages.deleteHistory`) make `--audit` flag a
class whose id is already correct for its own namespace; those hand-maintained
classes and their call sites are left untouched. Use `--docs-only` to refresh
their documentation without changing behaviour.
